# 5.2 · Ошибка 400 в Postman

Right Line, первый этап · тема: валидация, ошибки Spring · сложность: средняя

## Условие

> Прилетел такой ответ на запрос в Postman. Что будем делать?

**Запрос**

```json
{
    "orgName": "Рога и копыта",
    "email": "roga.mail.ru",
    "taxNumber": "1234567890"
}
```

**Ответ**

```
HTTP 400
{
    "timestamp": "2025-03-26T10:38:46.226+00:00",
    "status": 400,
    "error": "Bad Request",
    "path": "/api/v3/organisation/register"
}
```

Уточнение интервьюера: "Можешь сказать конкретно, что не так?" Ответа "запрос не прошел валидацию" мало.

<details>
<summary><b>Решение</b></summary>

**Проблема в запросе.** В `"email": "roga.mail.ru"` нет `@`, это не email. Скорее всего, его отбила валидация на бэкенде.

Другие гипотезы:
- `taxNumber` похож на ИНН. У ИНН есть контрольная сумма, и `1234567890` может ее не пройти. Еще бэкенд может ждать число вместо строки или другую длину;
- в запросе может не хватать обязательных полей: это регистрация, а пароля или контактного лица нет. Надо свериться с контрактом метода.

**Проблема в ответе.** Поля `timestamp`, `status`, `error`, `path` - стандартный ответ Spring Boot на ошибку, которую разработчик не обработал. Если назовешь это на собесе, интервьюер оценит.

В ответе не сказано, что именно не так: ни поля, ни причины, клиенту остается гадать. Ответ на ошибку валидации должен содержать сообщение или список ошибок по полям, например "email: неверный формат". Это отдельный дефект на бэкенд.

**Что делаю по шагам.**
1. Сверяю запрос с контрактом: состав полей, типы, форматы.
2. Исправляю email и повторяю запрос.
3. Если снова `400`, иду в логи сервиса или к разработчику: из ответа причину не узнать.
4. Завожу задачу на понятные ошибки валидации.

</details>
