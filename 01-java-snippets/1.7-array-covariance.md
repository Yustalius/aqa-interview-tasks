# 1.7 · Ковариантность массивов

🟡 надо подумать · тема: массивы и дженерики · Ланит

## Условие

Выполнится ли этот код? Если да, то почему, если нет, то почему.

```java
public class Main {
    public static void main(String[] args) {
        Object[] objects = new String[3];
        objects[0] = "hello";
        objects[1] = 42;
    }
}
```

Дополнительно: что будет, если сделать то же самое с `List`?

<details>
<summary><b>Решение</b></summary>

**Ответ.** Код **скомпилируется**, но упадёт при выполнении на строке `objects[1] = 42` с `ArrayStoreException: java.lang.Integer`.

**Почему.** Массивы в Java ковариантны: раз `String` наследник `Object`, то `String[]` можно положить в переменную типа `Object[]`. Компилятор видит тип `Object[]`, а в него можно класть что угодно, поэтому ошибок не находит.

Но в памяти лежит массив строк, и при каждой записи он проверяет тип элемента. `"hello"` проходит, а `42` (после автоупаковки это `Integer`) в массив строк не помещается, и прилетает исключение.

`3` в `new String[3]` — это просто размер массива, а не элемент.

**С `List` так не получится:**

```java
List<Object> list = new ArrayList<String>(); // ошибка компиляции
```

Дженерики **инвариантны**: `List<String>` не считается подтипом `List<Object>`. Ошибка ловится на этапе компиляции, а не в рантайме. Дженерики сделали такими как раз затем, чтобы не повторить проблему массивов.

</details>
