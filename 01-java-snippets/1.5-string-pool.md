# 1.5 · Сравнение строк

🟡 надо подумать · тема: String pool · Ланит

## Условие

Что выведет код?

```java
public class StringConcatenationDemo {
    public static void main(String[] args) {
        String s1 = "Hello" + " World";
        String s2 = "Hello World";

        String part = " World";
        String s3 = "Hello" + part;

        System.out.println(s1 == s2);
        System.out.println(s2 == s3);
    }
}
```

Вопрос интервьюера: как сделать второе сравнение `true`? Назови два способа.

<details>
<summary><b>Решение</b></summary>

**Ответ.**

```
true
false
```

**Почему.** В Java есть **пул строк**: строковые литералы хранятся в нём в одном экземпляре. Если в двух местах программы написать `"Hello World"`, обе переменные получат ссылку на одну и ту же строку из пула.

- `s1 = "Hello" + " World"` — склейка двух литералов. Компилятор вычисляет её заранее, и в коде остаётся литерал `"Hello World"` из пула. `s2` указывает туда же, поэтому `s1 == s2` даёт `true`.
- `s3 = "Hello" + part` — склейка с **переменной**. Компилятор не знает, что окажется в `part` к моменту выполнения, поэтому строка собирается в рантайме и создаётся новым объектом мимо пула. Ссылки разные, поэтому `s2 == s3` даёт `false`.

**Два способа получить `true`.**

```java
// 1. final: переменная становится константой,
//    и компилятор снова склеит строку заранее
final String part = " World";

// 2. intern(): вручную взять строку из пула
System.out.println(s2 == s3.intern());
```

Обязательно добавь: в реальном коде строки сравнивают только через `equals`. Сравнение через `==` даёт плавающие баги, потому что результат зависит от того, откуда пришла строка.

</details>
