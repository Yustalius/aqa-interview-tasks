# 1.8 · Статический метод и наследование

Ланит · тема: ООП · сложность: сложная

## Условие

Перед задачей интервьюер спросил: можно ли переопределить статический метод?

Какие три строки выведет код?

```java
class Parent {
    public static String getEnv() {
        return "PROD";
    }

    public String getDynamicEnv() {
        return getEnv();
    }
}

class Child extends Parent {
    public static String getEnv() {
        return "TEST";
    }
}

public class Inheritance {
    public static void main(String[] args) {
        Parent p = new Child();

        System.out.println(p.getEnv());
        System.out.println(p.getDynamicEnv());
        System.out.println(Child.getEnv());
    }
}
```

<details>
<summary><b>Решение</b></summary>

**Ответ.**

```
PROD
PROD
TEST
```

**Переопределить статический метод нельзя.** В наследнике можно объявить статический метод с той же сигнатурой, но это сокрытие (hiding), а не переопределение (overriding). Для обычного метода версия выбирается в рантайме по реальному объекту, на этом держится полиморфизм. Для статического версия выбирается при компиляции: по типу переменной или по классу, где написан вызов.

В программе три независимых метода: `Parent.getEnv()`, `Parent.getDynamicEnv()` и `Child.getEnv()`. Последний с родительским не связан, его можно перенести в любой другой класс, и вывод не изменится.

**Построчно.**

1. `p.getEnv()` - статика через переменную. Компилятор смотрит на тип переменной (`Parent`), а не на объект внутри (`Child`), и вызывает `Parent.getEnv()`: `PROD`. IDE подсвечивает такой вызов, статику вызывают через имя класса.
2. `p.getDynamicEnv()` - обычный метод, в `Child` он не переопределен, выполняется код из `Parent`. Вызов `getEnv()` внутри привязан к классу `Parent`: `PROD`.
3. `Child.getEnv()` - явный вызов через класс `Child`: `TEST`.

**Для сравнения.** Если бы `Child` переопределил обычный метод `getDynamicEnv()`, то `p.getDynamicEnv()` вызвал бы версию из `Child`.

**Как это выглядит в автотестах.** Конфиг окружения лежит в статических методах, и его "переопределяют" в наследнике для другого стенда. Тесты продолжают ходить на PROD.

</details>
