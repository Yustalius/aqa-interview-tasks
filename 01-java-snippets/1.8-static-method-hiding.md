# 1.8 · Статический метод и наследование

🔴 с подвохом · тема: ООП · Ланит

## Условие

Наводящий вопрос перед задачей: **можно ли переопределить статический метод?**

Какие три строки выведет код?

```java
class Parent {
    public static String getEnv() {
        return "PROD";
    }

    public String getDynamicEnv() {
        return getEnv();
    }
}

class Child extends Parent {
    public static String getEnv() {
        return "TEST";
    }
}

public class Inheritance {
    public static void main(String[] args) {
        Parent p = new Child();

        System.out.println(p.getEnv());
        System.out.println(p.getDynamicEnv());
        System.out.println(Child.getEnv());
    }
}
```

<details>
<summary><b>Решение</b></summary>

**Ответ.**

```
PROD
PROD
TEST
```

**Можно ли переопределить статический метод? Нет.** В наследнике можно объявить статический метод с той же сигнатурой, но это не переопределение (overriding), а **сокрытие** (hiding). У обычного метода вызываемая версия выбирается в рантайме по реальному объекту, в этом и есть полиморфизм. У статического метода версия выбирается при компиляции по типу переменной или по классу, в котором написан вызов.

Проще говоря, в программе три независимых метода: `Parent.getEnv()`, `Parent.getDynamicEnv()` и `Child.getEnv()`. Последний никак не связан с родительским, его можно было бы положить в любой другой класс, и результат не изменился бы.

**Построчно.**

1. `p.getEnv()`: статика, вызванная через переменную. Компилятор смотрит на **тип переменной** (`Parent`), а не на объект внутри (`Child`), и вызывает `Parent.getEnv()`. Выведет `PROD`. Вызывать статику через объект вообще плохая практика, IDE это подсвечивает.
2. `p.getDynamicEnv()`: обычный метод, в `Child` не переопределён, поэтому выполняется код из `Parent`. Внутри него `getEnv()` привязан к классу `Parent`. Выведет `PROD`.
3. `Child.getEnv()`: явный вызов через класс `Child`. Выведет `TEST`.

**Для сравнения.** Если бы в `Child` переопределили обычный метод `getDynamicEnv()`, то `p.getDynamicEnv()` вызвал бы версию из `Child`: для нестатических методов полиморфизм работает.

**Где это стреляет в автотестах.** Конфиг окружения лежит в статических методах, а его «переопределяют» в классе-наследнике для другого стенда. Тесты продолжают ходить на PROD.
