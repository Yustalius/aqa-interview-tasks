# Блок 4. Тест-дизайн API

Дают контракт метода и просят накидать проверки. Нужен чек-лист тезисами, оформлять тест-кейсы не надо. Оценивают, насколько широко и по какой структуре ты покрыл метод.

Порядок ответа:

1. Уточнить требования. В контракт часто кладут странность, которую тестировщик должен заметить.
2. Позитивный сценарий: система работает при правильном использовании.
3. Негативные сценарии: авторизация, невалидные данные, граничные значения.
4. Протокол: метод, заголовки, коды ответа, время ответа.
