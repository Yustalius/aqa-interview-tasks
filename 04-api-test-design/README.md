# Блок 4. Тест-дизайн API

Формат: дают контракт метода и просят накидать проверки. Нужен чек-лист тезисами, а не оформленные тест-кейсы. Смотрят на широту и структуру, а не на количество пунктов.

Порядок ответа везде один:

1. **Уточнить требования.** Прочитать контракт внимательно и задать вопросы. В контракт часто специально кладут странность, которую тестировщик должен заметить.
2. **Позитивный сценарий.** Сначала убеждаемся, что система работает при правильном использовании.
3. **Негативные сценарии.** Авторизация, невалидные данные, граничные значения.
4. **Протокол.** Метод, заголовки, коды ответа, время ответа.
