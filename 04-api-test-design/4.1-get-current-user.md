# 4.1 · Метод получения текущего пользователя

Озон, технический скрининг · тема: чек-лист по контракту · сложность: легкая

## Условие

> Метод получения информации о текущем пользователе

```
Request:

GET /user

Response:

{"phone": "string",
 "name": "string",
 "email": "string",
 "birthDate": "number",
 "img": "string",
}
```

Накидай тезисы проверок: как бы ты тестировал этот метод.

Наводящий вопрос интервьюера: "Как сервер понимает, кто текущий пользователь?"

<details>
<summary><b>Решение</b></summary>

### 1. Вопросы к контракту

Сначала задай вопросы, проверки потом. В контракте есть детали, которые легко пропустить:

- `birthDate: number`. Все поля строки, а дата число. Скорее всего, это timestamp (секунды или миллисекунды от 1 января 1970 года), но формат и единицы надо уточнить.
- Висячая запятая после `img`. Такой JSON невалиден. Это опечатка в документации или сервер так и отвечает?
- `phone`. Формат: `+7...`, `8...`, со скобками и дефисами или только цифры? Бывают ли иностранные номера?
- `name`. Только имя или полное ФИО?
- `email`. Есть ли ограничения по доменам?
- `img`. Это ID картинки или ссылка? Что приходит, если аватара нет: `null`, пустая строка или поле пропадает?

### 2. Как сервер понимает, кто пользователь

В запросе нет ни ID, ни параметров, это не `GET /user/{id}`. Значит, пользователь определяется по авторизации: токену в заголовке `Authorization` или сессионной куке. Сервер разбирает токен и отдает данные его владельца. Отсюда проверки авторизации.

### 3. Чек-лист

**Позитивные:**
- валидный токен → `200`, в ответе данные владельца токена;
- структура по контракту: все пять полей на месте, типы совпадают;
- значения в нужных форматах: телефон, email, дата рождения, `img`;
- пользователь с незаполненными необязательными полями: что приходит в ответе.

**Авторизация:**
- без токена → `401 Unauthorized`;
- протухший, отозванный или поддельный токен → `401`;
- токен пользователя А не возвращает данные пользователя Б.

`401` и `403` не путай: `401` - "не знаю, кто ты", `403` - "знаю, кто ты, но доступа не дам".

**Протокол:**
- `Content-Type: application/json`;
- `POST`, `DELETE` и другие методы на `/user` → `405 Method Not Allowed`, если они не предусмотрены;
- время ответа в пределах требований.

</details>
