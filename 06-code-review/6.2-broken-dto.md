# 6.2 · Сломанный DTO-класс

Сбер, риск-стратегии · тема: Lombok, Jackson · сложность: средняя

## Условие

Писать код не нужно. Проревьюй класс: что так, что не так, какие рекомендации. Рассуждай вслух.

Файл `BrokenStepDto.java`:

```java
package ru.test.my;

@Data
@FieldDefaults(level = AccessLevel.PRIVATE)
@AllArgsConstructor
@NoArgsConstructor
public class brokenStepDto {

    public String caseId;
    public String config_Id;
    private String name;
    // private String class;
    @JsonProperty("myTrace")
    private String Trace;
    private String dateStart

    public BrokenStepDto () {}

    public BrokenStepDto(String caseId, String config_Id, String name, String Trace, Date dateStart) {
        this.caseId = caseId;
        this.config_Id = config_Id;
        this.name = name;
        this.Trace = Trace;
        this.dateStart = dateStart;
    }

    public BrokenStepDto(String caseId, String name) {
        this.caseId = caseId;
        this.name = name;
    }

    public String getCaseId() {return caseId;}

    public void setCaseId(String caseId) {this.caseId = caseId;}

    public String getSpaceId() {return spaceId;}

    public void setSpaceId(String spaceId) {this.spaceId = spaceId;}
}
```

В конце перепиши класс так, как он должен выглядеть.

<details>
<summary><b>Решение</b></summary>

Замечания удобно делить на две группы: что не даст скомпилироваться и что скомпилируется, но плохо. Всего проблем одиннадцать. Все на собесе не ждут, но чем больше назовешь, тем лучше.

### Не скомпилируется

1. Класс `brokenStepDto` с маленькой буквы, а файл `BrokenStepDto.java`. Имя публичного класса обязано совпадать с именем файла, и классы в Java пишут с большой буквы.
2. Поэтому конструкторы `BrokenStepDto(...)` не совпадают с именем класса, и компилятор считает их методами без типа возврата.
3. После `private String dateStart` нет точки с запятой.
4. Конструктор принимает `Date dateStart`, а поле объявлено как `String`.
5. `getSpaceId` и `setSpaceId` обращаются к полю `spaceId`, которого в классе нет.
6. Нет импортов: ни Lombok, ни `@JsonProperty`, ни `Date`. Помнить сами импорты не нужно, достаточно заметить, что их нет.
7. Если починить имя класса, `@NoArgsConstructor` и `@AllArgsConstructor` сгенерируют конструкторы, которые уже написаны руками. Два одинаковых конструктора - ошибка компиляции.

### Скомпилируется, но плохо

8. `@Data` уже генерирует геттеры и сеттеры для всех полей, ручные лишние. Либо Lombok, либо руками.
9. Поля публичные, а у DTO они закрыты и доступны через геттеры. `@FieldDefaults(level = PRIVATE)` делает приватными только поля без модификатора, явный `public` он не трогает. Аннотация и поля противоречат друг другу. Проще убрать `@FieldDefaults` и написать `private`.
10. `config_Id` написан в snake_case, `Trace` с большой буквы. Поля в Java пишут в camelCase: `configId`, `trace`. Если в JSON поле называется иначе, его маппят через `@JsonProperty`.
11. Закомментированное `// private String class` надо удалить или вернуть. Только `class` - зарезервированное слово, и так поле назвать нельзя. Если такое поле есть в JSON, его называют по-другому:

    ```java
    @JsonProperty("class")
    private String clazz;
    ```

Еще стоит спросить у интервьюера про тип `dateStart`: если это дата, лучше `LocalDateTime` из `java.time`, чем устаревший `java.util.Date`. И зачем `Trace` маппится на `myTrace`: если причины нет, поле проще назвать как в JSON.

### Как должен выглядеть класс

```java
package ru.test.my;

import com.fasterxml.jackson.annotation.JsonProperty;
import lombok.AllArgsConstructor;
import lombok.Data;
import lombok.NoArgsConstructor;

@Data
@AllArgsConstructor
@NoArgsConstructor
public class BrokenStepDto {

    private String caseId;
    private String configId;
    private String name;

    @JsonProperty("myTrace")
    private String trace;

    private String dateStart;   // или LocalDateTime, уточнить формат
}
```

Lombok сгенерирует геттеры, сеттеры, оба конструктора, `equals`, `hashCode` и `toString`. Конструктор на два поля Lombok не создает: его можно оставить руками или заменить на `@Builder`.
