# 6.1 · Утилитный класс для автотестов

🟡 надо подумать · тема: equals, Stream API, ожидания · Сбер, команда ИИ-агентов

## Условие

> Найдите 3–5 проблем в коде.
> Объясните, почему это плохо для автотестов.
> Перепишите методы так, чтобы они соответствовали современным практикам Java и AQA.

```java
public class TestValidator {
    public static boolean isUserActive(User user) {
        if (user.getStatus() == "ACTIVE") {
            return true;
        }
        return false;
    }

    public static List<String> filterFailed(List<String> testResults) {
        List<String> failed = new ArrayList<>();
        for (String res : testResults) {
            if (res.contains("FAIL")) {
                failed.add(res);
            }
        }
        return failed;
    }

    public static void waitForPage() {
        try {
            Thread.sleep(5000);
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}

class User {
    private String status;
    public String getStatus() { return status; }
}
```

<details>
<summary><b>Решение</b></summary>

### Что делает код

Сначала коротко перескажи. `isUserActive` проверяет, активен ли пользователь. `filterFailed` возвращает из списка результатов только строки с `FAIL`, то есть упавшие (по названию можно подумать наоборот). `waitForPage` ждёт загрузку страницы, тупо пять секунд. `User` — модель с одним полем.

### Проблемы

**`isUserActive`**

1. **`==` для строк.** Сравниваются ссылки, а не содержимое (см. [1.5](../01-java-snippets/1.5-string-pool.md)). Статус, пришедший из JSON или БД, будет другим объектом, сравнение даст `false`, и тест упадёт на рабочем функционале. Нужен `equals`.
2. **Нет защиты от `null`.** Если `user` равен `null`, вылетит `NullPointerException`. Порядок `"ACTIVE".equals(user.getStatus())` спасает хотя бы от `null` в статусе.
3. **Статус — «магическая строка».** Опечатку `"ACTVE"` компилятор не заметит, а проверка будет молча возвращать `false`. Статусов конечное число, значит, им место в enum.
4. **`if (...) return true; return false;`** — лишняя конструкция: условие уже и есть `boolean`.

**`filterFailed`**

5. **Имя вводит в заблуждение.** «Отфильтровать упавшие» можно прочитать и как «убрать упавшие». Понятнее `getFailedResults`.
6. **`contains("FAIL")` слишком широкий.** Поймает и `FAILED`, и `NOT_FAILED`, если такой статус появится. Нужно точное совпадение со статусом.
7. **Цикл можно заменить стримом.** Новый список, цикл, `if`, `add` — это ручная реализация `filter`.

**`waitForPage`**

8. **`Thread.sleep(5000)` — жёсткое ожидание.** Главный враг автотестов. Если страница загрузилась за секунду, тест 4 секунды простаивает, и прогон из сотни тестов растягивается на минуты. Если страница грузится 6 секунд, тест падает: получаем флаки. Нужно ждать условие, а не время. А лучше настроить ожидания глобально на уровне фреймворка.
9. **`catch (Exception e)` + `printStackTrace()`.** Ловится вообще всё, ошибка просто печатается в консоль и проглатывается, а тест идёт дальше как ни в чём не бывало. `InterruptedException` надо ловить отдельно и восстанавливать флаг прерывания, а для вывода использовать логгер: в CI вывод `printStackTrace` легко потерять.

**`User`**

10. Статус нельзя задать: нет ни конструктора, ни сеттера. Поле всегда `null`.

### Как переписать

```java
public enum UserStatus { ACTIVE, BLOCKED, DELETED }

public class User {
    private UserStatus status;
    // конструктор, геттер (или Lombok @Data)
}

public class TestValidator {

    public static boolean isUserActive(User user) {
        return user != null && user.getStatus() == UserStatus.ACTIVE;
    }

    public static List<String> getFailedResults(List<String> testResults) {
        return testResults.stream()
                .filter(result -> result.contains("FAIL"))
                .toList();                 // Java 16+, раньше .collect(Collectors.toList())
    }
}
```

Сравнивать enum через `==` безопасно: каждая константа существует в одном экземпляре, и `==` не падает на `null` (см. [1.6](../01-java-snippets/1.6-enum-comparison.md)).

Если статус остаётся строкой, то так:

```java
return user != null && "ACTIVE".equals(user.getStatus());
```

**Ожидание** — по условию, а не по таймеру:

```java
// Selenide: ждём конкретный элемент, по умолчанию до 4 секунд
$("#content").shouldBe(visible);

// Selenium
new WebDriverWait(driver, Duration.ofSeconds(5))
        .until(ExpectedConditions.visibilityOfElementLocated(By.id("content")));
```

Синтаксис `WebDriverWait` наизусть никто не ждёт. Достаточно сказать: «Уберу `sleep`, сделаю явное ожидание по условию через Selenium или Selenide, а таймауты вынесу в конфиг фреймворка».
