# 6.1 · Утилитный класс для автотестов

Сбер, команда ИИ-агентов · тема: equals, Stream API, ожидания · сложность: средняя

## Условие

> Найдите 3-5 проблем в коде.
> Объясните, почему это плохо для автотестов.
> Перепишите методы так, чтобы они соответствовали современным практикам Java и AQA.

```java
public class TestValidator {
    public static boolean isUserActive(User user) {
        if (user.getStatus() == "ACTIVE") {
            return true;
        }
        return false;
    }

    public static List<String> filterFailed(List<String> testResults) {
        List<String> failed = new ArrayList<>();
        for (String res : testResults) {
            if (res.contains("FAIL")) {
                failed.add(res);
            }
        }
        return failed;
    }

    public static void waitForPage() {
        try {
            Thread.sleep(5000);
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}

class User {
    private String status;
    public String getStatus() { return status; }
}
```

<details>
<summary><b>Решение</b></summary>

### Что делает код

Сначала коротко перескажи. `isUserActive` проверяет, активен ли пользователь. `filterFailed` возвращает из списка результатов строки с `FAIL`, то есть упавшие, хотя по названию можно подумать наоборот. `waitForPage` ждет загрузку страницы ровно пять секунд. `User` - модель с одним полем.

### Проблемы

**`isUserActive`**

1. `==` для строк сравнивает ссылки (см. [1.5](../01-java-snippets/1.5-string-pool.md)). Статус из JSON или БД будет другим объектом, сравнение даст `false`, и тест упадет на рабочем функционале. Нужен `equals`.
2. Нет защиты от `null`: если `user` равен `null`, вылетит `NullPointerException`. Порядок `"ACTIVE".equals(user.getStatus())` спасает хотя бы от `null` в статусе.
3. Статус задан строкой. Опечатку `"ACTVE"` компилятор не заметит, проверка будет молча возвращать `false`. Статусов конечное число, их место в enum.
4. `if (...) return true; return false;` лишнее, условие само `boolean`.

**`filterFailed`**

5. Имя путает: "отфильтровать упавшие" читается и как "убрать упавшие". Понятнее `getFailedResults`.
6. `contains("FAIL")` ловит и `FAILED`, и `NOT_FAILED`, если такой статус появится. Нужно точное совпадение.
7. Новый список, цикл, `if` и `add` повторяют вручную то, что делает `filter` в стриме.

**`waitForPage`**

8. `Thread.sleep(5000)` ждет фиксированное время. Страница загрузилась за секунду, а тест простаивает еще четыре, и сотня тестов прогоняется на минуты дольше. Страница грузится шесть секунд, и тест падает. Ждать надо условие, а таймауты лучше настроить глобально во фреймворке.
9. `catch (Exception e)` с `printStackTrace()` ловит все подряд, печатает ошибку в консоль и глотает ее, тест идет дальше. `InterruptedException` ловят отдельно и восстанавливают флаг прерывания, а пишут через логгер: вывод `printStackTrace` в CI легко потерять.

**`User`**

10. Статус нельзя задать: нет ни конструктора, ни сеттера, поле всегда `null`.

### Как переписать

```java
public enum UserStatus { ACTIVE, BLOCKED, DELETED }

public class User {
    private UserStatus status;
    // конструктор, геттер (или Lombok @Data)
}

public class TestValidator {

    public static boolean isUserActive(User user) {
        return user != null && user.getStatus() == UserStatus.ACTIVE;
    }

    public static List<String> getFailedResults(List<String> testResults) {
        return testResults.stream()
                .filter(result -> result.contains("FAIL"))
                .toList();                 // Java 16+, раньше .collect(Collectors.toList())
    }
}
```

Enum безопасно сравнивать через `==`: каждая константа существует в одном экземпляре, и `==` не падает на `null` (см. [1.6](../01-java-snippets/1.6-enum-comparison.md)).

Если статус остается строкой:

```java
return user != null && "ACTIVE".equals(user.getStatus());
```

Ожидание по условию вместо таймера:

```java
// Selenide: ждём конкретный элемент, по умолчанию до 4 секунд
$("#content").shouldBe(visible);

// Selenium
new WebDriverWait(driver, Duration.ofSeconds(5))
        .until(ExpectedConditions.visibilityOfElementLocated(By.id("content")));
```

Синтаксис `WebDriverWait` наизусть не спрашивают. Хватит сказать: "Уберу `sleep`, сделаю явное ожидание по условию через Selenium или Selenide, а таймауты вынесу в конфиг".
