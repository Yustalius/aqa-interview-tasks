# 3.1 · users и orders

Тестовое задание по ссылке · тема: SELECT, JOIN · сложность: легкая

## Условие

Есть две связанные таблицы.

**`users`**

| id | name | email |
|---|---|---|
| 1 | Борис | boris@test.com |
| 2 | Анна | anna@test.com |
| 3 | Богдан | bogdan@test.com |
| 4 | Виктор | victor@test.com |
| 5 | Белла | bella@test.com |
| 6 | Борислав | borislav@test.com |

**`orders`**

| id | user_id | amount | status |
|---|---|---|---|
| 1 | 1 | 1500 | PAID |
| 2 | 2 | 500 | CREATED |
| 3 | 3 | 3200 | PAID |

Поле `orders.user_id` ссылается на `users.id`.

Напишите запросы:

1. Все пользователи, имя которых начинается с буквы "Б".
2. Заказы с суммой больше 1000, отсортированные по сумме по убыванию, не более пяти строк.
3. Список заказов с именами пользователей, которым они принадлежат, через `INNER JOIN`.

Вопросы по ходу: "Почему ты используешь JOIN? Зачем соединяешь таблицы?", "Почему не через звездочку?"

Вопросы в конце: чем отличаются `OUTER JOIN` и `LEFT JOIN`? Приведи примеры оконных функций.

Данные для проверки лежат в [`setup.sql`](setup.sql).

<details>
<summary><b>Решение</b></summary>

**Запрос 1.**

```sql
SELECT *
FROM users
WHERE name LIKE 'Б%';
```

`LIKE` ищет по шаблону, `%` означает любое количество любых символов. Вернет Бориса, Богдана, Беллу и Борислава.

**Запрос 2.**

```sql
SELECT *
FROM orders
WHERE amount > 1000
ORDER BY amount DESC
LIMIT 5;
```

`DESC` сортирует по убыванию, `ASC` по возрастанию, их часто путают. Вернет две строки: заказ 3 на 3200 и заказ 1 на 1500. `LIMIT 5` обрезал бы результат до пяти строк, но их здесь всего две.

**Запрос 3.**

```sql
SELECT o.id, o.amount, o.status, u.name
FROM orders o
INNER JOIN users u ON o.user_id = u.id;
```

`o` и `u` - алиасы, короткие имена таблиц. Объявляются они в `FROM` и `JOIN`, без этого `o.id` не сработает. Вернет три строки: (1, 1500, PAID, Борис), (2, 500, CREATED, Анна), (3, 3200, PAID, Богдан). Пользователи без заказов в результат не попадут.

**Зачем JOIN.** Имя пользователя лежит в `users`, сумма и статус в `orders`. Чтобы получить их в одной строке, таблицы соединяют по связи: внешний ключ `orders.user_id` равен первичному ключу `users.id`. `INNER JOIN` оставляет только строки, для которых нашлась пара. Можно писать просто `JOIN`, это то же самое.

**Почему не звездочка.** При джойне `*` вытащит все колонки обеих таблиц, включая два разных `id`, а в реальных таблицах колонок десятки. Явный список понятнее, и если в таблицу добавят колонку, результат запроса в автотесте не изменится.

**`OUTER JOIN` и `LEFT JOIN`.** `LEFT JOIN` - сокращение от `LEFT OUTER JOIN`, это одно и то же. Внешние джойны бывают трех видов:
- `LEFT` - все строки левой таблицы и совпавшие из правой, где пары нет, будет `NULL`;
- `RIGHT` - то же зеркально;
- `FULL` - все строки обеих таблиц.

**Оконные функции** считают агрегат по группе строк, но в отличие от `GROUP BY` не схлопывают их в одну. Примеры: `ROW_NUMBER()`, `RANK()`, `SUM(...) OVER (...)`.

```sql
-- пронумеровать заказы каждого пользователя от самого дорогого
SELECT user_id, amount,
       ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY amount DESC) AS rn
FROM orders;
```
