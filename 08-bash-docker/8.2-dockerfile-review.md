# 8.2 · Разобрать Dockerfile

Right Line, первый этап · тема: Docker · сложность: средняя

## Условие

Блок "Docker и docker compose". Опиши, что делает каждая строка.

```dockerfile
FROM bellsoft/liberica-openjdk-alpine:21

LABEL maintainer=qa-team
WORKDIR /app

ADD pcr-mock-app.jar /app/pcr-mock-app.jar
ADD application.yml /app/config/application.yml
ADD logback.xml /app/config/logback.xml
RUN apk update && apk upgrade --no-cache

CMD ["java", "-jar", "/app/pcr-mock-app.jar"]
```

Вопросы по порядку:
1. Что делает каждая инструкция?
2. Чем `RUN` отличается от `CMD`?
3. Что бы ты здесь улучшил?

<details>
<summary><b>Решение</b></summary>

Dockerfile описывает, как собрать образ: на какой основе, какие файлы положить внутрь и что запустить. Большую часть можно понять по английским словам, даже не зная синтаксиса.

### 1. Построчно

| Инструкция | Что делает |
|---|---|
| `FROM bellsoft/liberica-openjdk-alpine:21` | Базовый образ: Alpine Linux с JDK 21 от BellSoft (Liberica - их сборка Java) |
| `LABEL maintainer=...` | Метаданные образа: кто его сопровождает |
| `WORKDIR /app` | Рабочая папка внутри контейнера, создается, если ее нет |
| `ADD pcr-mock-app.jar ...` | Копирует jar-файл приложения в образ |
| `ADD application.yml ...`, `ADD logback.xml ...` | Копирует конфиги приложения и логирования |
| `RUN apk update && apk upgrade --no-cache` | При сборке обновляет пакеты Alpine (`apk` - пакетный менеджер Alpine) |
| `CMD ["java", "-jar", ...]` | При старте контейнера запускает приложение из jar |

jar - Java-программа, упакованная в один файл. Ее запускают командой `java -jar`, без Gradle и IDE.

### 2. `RUN` и `CMD`

- `RUN` выполняется при сборке образа (`docker build`), результат сохраняется в образе. Так ставят пакеты и готовят окружение.
- `CMD` выполняется при запуске контейнера (`docker run`). Это команда по умолчанию: ее можно переопределить при запуске, и из нескольких `CMD` в файле работает последний.

### 3. Что улучшить

1. `COPY` вместо `ADD`. `ADD` еще умеет скачивать по URL и распаковывать архивы. Для обычного копирования берут `COPY`, `ADD` - только когда нужны эти возможности.
2. JRE вместо JDK. JDK нужен для разработки, для запуска хватит JRE (`bellsoft/liberica-openjre-alpine:21`). Образ меньше, лишних утилит меньше.
3. Порядок слоев. Каждая инструкция - слой, Docker кеширует слои. `RUN apk ...` стоит поставить до копирования jar: сейчас каждая пересборка jar сбрасывает кеш, и пакеты обновляются заново.
4. `apk update` лишний: `--no-cache` сам берет свежий список пакетов и не оставляет кеш в образе.
5. Относительные пути. `WORKDIR /app` задан, а пути все равно абсолютные. Можно писать `COPY pcr-mock-app.jar app.jar` и `CMD ["java", "-jar", "app.jar"]`. Spring Boot при этом сам подхватит конфиги из `./config/` относительно рабочей папки.
6. Контейнер работает от root. Лучше создать обычного пользователя и переключиться на него через `USER`.
7. Нет `EXPOSE`, порт приложения нигде не указан.
8. Нет `HEALTHCHECK`. Контейнер может работать, когда приложение внутри упало или зависло. Healthcheck периодически опрашивает приложение, например `/actuator/health`, и Docker видит, живо ли оно.

И `.dockerignore`, чтобы в контекст сборки не попадало лишнее.

Вариант после исправлений: [`Dockerfile.fixed`](Dockerfile.fixed). Порт и адрес healthcheck в нем условные, их надо уточнить у разработчиков.

</details>
