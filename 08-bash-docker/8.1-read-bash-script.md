# 8.1 · Прочитать bash-скрипт

🟡 надо подумать · тема: bash · Right Line, первый этап

## Условие

Интервьюер показывает экран: «Вот наш скрипт. Можешь его прочитать?»

```bash
if [[ $BANK == "alfa" || $BANK == "rsb" || $BANK == "domrf" ]]; then
    if [[ $SERVICE == "pcr-processing-client-app" ]]; then
        PATH_TO_DIST="/var/opt/qa/nextcloud/banks/${BANK}/pcr-processing-customer-app/latest"
    else
        PATH_TO_DIST="/var/opt/qa/nextcloud/banks/${BANK}/${SERVICE}/latest"
    fi
fi

if { [[ $BANK == alfa ]] || [[ $BANK == basic ]]; } && [[ $SERVICE == pcr-processing* ]]; then
    sh -x install_docker_pcr-processing.sh $BANK $PATH_TO_DIST $DEPLOY_DIR
fi
```

Подсказка: сравни списки банков в первом и втором блоке.

<details>
<summary><b>Решение</b></summary>

Отвечать надо в два захода: сначала пересказать, что скрипт делает, без оценок. Только потом говорить о проблемах. Кто начинает искать ошибки в коде, который ещё не понял, выглядит хуже.

### Заход 1: что делает скрипт

Мини-словарь: `$BANK` — значение переменной, `[[ ... ]]` — условие, `then` — «то», `fi` закрывает `if` (это `if` задом наперёд), `*` — «что угодно дальше».

**Первый блок.** Если переменная `BANK` равна `alfa`, `rsb` или `domrf`, собираем путь к дистрибутиву `PATH_TO_DIST`:
- для сервиса `pcr-processing-client-app` путь ведёт в каталог `pcr-processing-customer-app`, то есть имя каталога отличается от имени сервиса;
- для остальных сервисов путь строится из имени сервиса напрямую.

**Второй блок.** Если `BANK` равен `alfa` или `basic` **и** имя сервиса начинается с `pcr-processing`, запускаем установочный скрипт и передаём ему банк, путь к дистрибутиву и каталог деплоя. `sh` запускает shell-скрипт, а `-x` включает трассировку: каждая команда печатается в лог.

### Заход 2: проблемы

1. **Списки банков не совпадают.** Путь собирается для `alfa`, `rsb`, `domrf`, а установка запускается для `alfa` и `basic`. Для `basic` установка стартует с **пустым** `PATH_TO_DIST`: путь для него никто не собрал. Для `rsb` и `domrf` путь собирается, но установка не запускается никогда.
2. **Аргументы сдвигаются.** Переменные в вызове без кавычек. Пустой `$PATH_TO_DIST` просто исчезнет из команды, и `DEPLOY_DIR` приедет в скрипт вторым аргументом вместо третьего. Установка пойдёт с неверными путями и без явной ошибки.
3. **Пробел в пути сломает вызов** по той же причине. Переменные надо брать в кавычки: `"$BANK" "$PATH_TO_DIST" "$DEPLOY_DIR"`.
4. **`client-app` → `customer-app`.** Легаси или опечатка? Как минимум нужен комментарий.
5. **Неизвестный банк никак не обрабатывается.** Скрипт молча идёт дальше с пустыми переменными. Нужна ветка с ошибкой и `exit 1`, а в начале скрипта `set -euo pipefail`, чтобы он падал на ошибках и неустановленных переменных.

Как это может выглядеть после исправлений: [`deploy.fixed.sh`](deploy.fixed.sh). Какие банки на самом деле нужны в каждом блоке, надо уточнить у автора скрипта.
