# 8.1 · Прочитать bash-скрипт

Right Line, первый этап · тема: bash · сложность: средняя

## Условие

Интервьюер показывает экран: "Вот наш скрипт. Можешь его прочитать?"

```bash
if [[ $BANK == "alfa" || $BANK == "rsb" || $BANK == "domrf" ]]; then
    if [[ $SERVICE == "pcr-processing-client-app" ]]; then
        PATH_TO_DIST="/var/opt/qa/nextcloud/banks/${BANK}/pcr-processing-customer-app/latest"
    else
        PATH_TO_DIST="/var/opt/qa/nextcloud/banks/${BANK}/${SERVICE}/latest"
    fi
fi

if { [[ $BANK == alfa ]] || [[ $BANK == basic ]]; } && [[ $SERVICE == pcr-processing* ]]; then
    sh -x install_docker_pcr-processing.sh $BANK $PATH_TO_DIST $DEPLOY_DIR
fi
```

Подсказка: сравни списки банков в первом и втором блоке.

<details>
<summary><b>Решение</b></summary>

Отвечай в два захода: сначала перескажи, что делает скрипт, без оценок, потом называй проблемы.

### Заход 1: что делает скрипт

Мини-словарь: `$BANK` - значение переменной, `[[ ... ]]` - условие, `then` - "то", `fi` закрывает `if` (это `if` задом наперед), `*` - "что угодно дальше".

**Первый блок.** Если `BANK` равен `alfa`, `rsb` или `domrf`, собираем путь к дистрибутиву `PATH_TO_DIST`:
- для сервиса `pcr-processing-client-app` путь ведет в каталог `pcr-processing-customer-app`, имя каталога отличается от имени сервиса;
- для остальных сервисов путь строится из имени сервиса.

**Второй блок.** Если `BANK` равен `alfa` или `basic` и имя сервиса начинается с `pcr-processing`, запускаем установочный скрипт и передаем ему банк, путь к дистрибутиву и каталог деплоя. `sh` запускает shell-скрипт, `-x` печатает в лог каждую выполненную команду.

### Заход 2: проблемы

1. Списки банков не совпадают. Путь собирается для `alfa`, `rsb`, `domrf`, а установка запускается для `alfa` и `basic`. Для `basic` установка стартует с пустым `PATH_TO_DIST`, путь для него никто не собрал. Для `rsb` и `domrf` путь собирается, но установка не запускается никогда.
2. Аргументы сдвигаются. Переменные в вызове не в кавычках, и пустой `$PATH_TO_DIST` просто выпадет из команды: `DEPLOY_DIR` придет в скрипт вторым аргументом вместо третьего. Установка пойдет с неверными путями без явной ошибки.
3. По той же причине вызов сломает пробел в пути. Переменные надо брать в кавычки: `"$BANK" "$PATH_TO_DIST" "$DEPLOY_DIR"`.
4. `client-app` ведет в каталог `customer-app`. Легаси это или опечатка, непонятно, нужен хотя бы комментарий.
5. Неизвестный банк никак не обрабатывается, скрипт молча идет дальше с пустыми переменными. Нужна ветка с ошибкой и `exit 1`, а в начале `set -euo pipefail`, чтобы скрипт падал на ошибках и неустановленных переменных.

Вариант после исправлений: [`deploy.fixed.sh`](deploy.fixed.sh). Какие банки на самом деле нужны в каждом блоке, надо уточнить у автора скрипта.
